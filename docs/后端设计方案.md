# 拾光集 · 后端设计方案（精简版）

> 场景收敛：**家庭相册，单机部署，单管理员 + 家人浏览**。
> 图片存储支持两种驱动：本地磁盘 或 S3 兼容对象存储（MinIO / R2 / OSS / COS），
> 一套代码、改配置切换。

---

## 1. 场景与目标

- 规模：照片 1~3 万张，原图均值 8MB → 总量 100~250 GB；写入低频（批量上传），读取为主。
- 部署：一台机器（NAS / 家用服务器 / 小 VPS），**单二进制 + Docker**，单人维护。
- 底线：**照片零丢失**（备份是设计的一部分，不是可选项）；上传自动剥离 GPS 隐私。
- 不做：多租户、评论、搜索、视频。规模就这么大，架构全程做减法。

## 2. 技术选型

| 组件 | 选择 | 一句话理由 |
|------|------|-----------|
| 语言/路由 | Go 1.22+，chi | 单二进制，交叉编译到 NAS 无痛 |
| 数据库 | SQLite（WAL） | 单机单写者，零运维；备份=复制文件 |
| 图片处理 | disintegration/imaging（纯 Go） | 零 cgo；家庭量级性能足够 |
| EXIF / BlurHash | goexif / go-blurhash | 方向矫正、拍摄时间、显影占位 |
| 对象存储 SDK | aws-sdk-go-v2 | 通吃所有 S3 兼容服务 |
| 前端 | 原型经 go:embed 打进二进制 | 部署只有一个文件 + 一个数据目录 |

## 3. 总体架构

```
                 ┌──────────────────────────────────────────┐
                 │            shiguang-server (Go)          │
  浏览器/手机     │  ┌────────┐  ┌─────────┐  ┌───────────┐  │
 ┌─────────┐JSON │  │ HTTP层 │─►│ Service │─►│  SQLite   │  │
 │ 前端原型 │◄───►│  │chi+auth│  │ 业务编排 │  └───────────┘  │
 └────┬────┘     │  └───┬────┘  └──┬───┬──┘  ┌───────────┐  │
      │图片       │      │(local直出)│   └────►│ BlobStore │──┼─► 本地盘  或  S3兼容桶
      └──────────┼──────┘    ┌─────▼────┐    │local │ s3 │  │
                 │           │ imgproc  │───►└───────────┘  │
                 │           │ worker×N │  变体/BlurHash     │
                 │           └──────────┘                   │
                 │  后台：GC(孤儿/回收站) · reaper(过期上传)   │
                 └──────────────────────────────────────────┘
```

两种模式 API 完全一致，只有图片字节路径不同：

| | local | s3 |
|---|---|---|
| 上传 | multipart 直传 API | 预签名 PUT 直传桶（字节不过应用） |
| 下载 | 本服务 `/img/*` 直出 | 桶/CDN 域名 |
| 选它当 | 图片和服务在同一台机器（NAS 典型） | 不想操心磁盘和备份，或要公网分享 |

**存储决策（一段话说清）**：家里有 NAS/大盘 → 用 local，简单直接，但必须配
§9 的备份纪律；没有可靠磁盘、或家人分布外网访问多 → 用 s3（推荐出流量免费的
Cloudflare R2，1~3 万张月成本 ≈ $2~4）。两个驱动共用**内容寻址 key**
（sha256），以后迁移 = `rclone sync` + 改 4 个环境变量，数据库一行不动。

## 4. 数据模型

```sql
CREATE TABLE nodes (
    id          TEXT PRIMARY KEY,          -- ULID（防枚举、时间有序）
    date        TEXT NOT NULL,             -- 'YYYY-MM-DD'
    title       TEXT NOT NULL,
    description TEXT NOT NULL DEFAULT '',
    created_at  TEXT NOT NULL, updated_at TEXT NOT NULL,
    deleted_at  TEXT                       -- 软删除（回收站，7 天后物理清理）
);
CREATE INDEX idx_nodes_timeline ON nodes(date DESC, id DESC) WHERE deleted_at IS NULL;

CREATE TABLE photos (
    id          TEXT PRIMARY KEY,          -- ULID
    node_id     TEXT NOT NULL REFERENCES nodes(id),
    caption     TEXT NOT NULL DEFAULT '',
    ord         INTEGER NOT NULL,          -- 留缝排序 100,200,300…重排=写一行
    status      TEXT NOT NULL DEFAULT 'pending',
                -- pending→processing→ready|failed（对应前端显影/曝光失败）
    fail_reason TEXT,
    sha256      TEXT, ext TEXT,
    width INTEGER, height INTEGER,
    blurhash TEXT, dominant TEXT, size_bytes INTEGER,
    taken_at    TEXT,                      -- EXIF 拍摄时间
    created_at  TEXT NOT NULL, updated_at TEXT NOT NULL,
    deleted_at  TEXT
);
CREATE INDEX idx_photos_node ON photos(node_id, ord) WHERE deleted_at IS NULL;
CREATE UNIQUE INDEX uq_node_sha ON photos(node_id, sha256)
    WHERE deleted_at IS NULL AND sha256 IS NOT NULL;    -- 同组防重复上传

CREATE TABLE upload_sessions (             -- 仅 s3 模式：预签名生命周期
    id TEXT PRIMARY KEY, photo_id TEXT NOT NULL,
    object_key TEXT NOT NULL, expect_size INTEGER NOT NULL,
    state TEXT NOT NULL DEFAULT 'issued',  -- issued|confirmed|expired
    expires_at TEXT NOT NULL, created_at TEXT NOT NULL
);
```

**Blob key 约定**（内容寻址，两驱动一致）：

```
orig/ab/cd/<sha256>.<ext>          原图（永久保留）
var/ab/cd/<sha256>/thumb.webp      336w  列表缩略（前端168px@2x）
var/ab/cd/<sha256>/md.webp         1200w 灯箱
var/ab/cd/<sha256>/lg.webp         2048w 双指缩放
staging/<ulid>.<ext>               s3 暂存，confirm 校验后转正
```

两个正确性要点：① 同一张图可被传进多个节点（blob 共享），**物理删除 blob 前
必须查无存活引用**（`WHERE sha256=? AND deleted_at IS NULL` 计数为 0）；
② 时间轴用两条查询取一页（先取节点，再 `node_id IN (...)` 批量取照片），无 N+1。

## 5. API（`/api/v1`，写接口 Bearer Token）

| 方法/路径 | 说明 |
|-----------|------|
| GET /timeline?cursor&limit | 逆序游标分页（cursor=base64(date\|id)） |
| GET /nodes/{id} · GET /photos/{id} · GET /stats | 详情 / 状态轮询 / 统计 |
| POST /nodes · PATCH /nodes/{id} · DELETE /nodes/{id} | 节点 CRUD（删=软删级联） |
| POST /nodes/{id}/photos | **local**：multipart 上传 |
| POST /uploads/presign → 客户端 PUT → POST /photos/{id}/confirm | **s3**：三步直传 |
| PATCH /photos/{id} · PUT /nodes/{id}/photos/order · DELETE /photos/{id} | 改注 / 重排 / 删 |
| GET /img/{key...} | local 模式图片直出（immutable 缓存） |
| GET /healthz | 探活 |

时间轴响应按前端渲染结构直接给齐：

```jsonc
{ "items": [{
    "id": "01J1ZK8Q...", "date": "2026-05-21",
    "title": "黄山两日", "description": "云海来得比预报早…",
    "photo_count": 5,
    "photos": [{
      "id": "01J1ZK9A...", "caption": "云海翻涌",
```

## 6. 上传与图片处理管线

```
local: multipart ─┐
                  ▼
s3: presign → [pending] → 原图落存储 → [processing] → 变体+元数据 → [ready]
                  │                        │  重试1次失败 ──────────► [failed]
   session 过期 ──► reaper 清 staging       │
                            服务重启：扫描卡住的 pending/processing 重新入队
```

处理步骤（worker pool，容量=CPU 核数，队列满仍收原图只是排队——绝不拒收资产）：

1. **校验**：魔数嗅探（仅 jpeg/png/webp）、30MB 上限、`DecodeConfig` 预读尺寸
   >60MP 拒绝（像素炸弹）；
2. **规范化**：EXIF Orientation 矫正、读拍摄时间；重编码输出 ⇒ 天然剥离全部
   EXIF（含 GPS）；
3. **变体**：thumb/md/lg 三档 webp q80，小图不放大；写临时 key 再改名（幂等可重入）；
4. **元数据**：BlurHash(4×3) + 主色 + 宽高，单事务回写 → ready。

**一致性一句话原则**：blob 先行、DB 断后；孤儿 blob 由每日 GC 对账清理（宽限
48h），悬空 DB 记录被 status 门控不外泄——任意时刻断电都收敛到安全态。

```go
// 存储抽象：换驱动=换实现，service 层零改动
type Store interface {
    Put(ctx context.Context, key string, r io.Reader, size int64, ct string) error
    Open(ctx context.Context, key string) (io.ReadCloser, error)
    Stat(ctx context.Context, key string) (int64, error)      // confirm 校验
    Delete(ctx context.Context, key string) error
    Rename(ctx context.Context, from, to string) error        // staging→正式
    List(ctx context.Context, prefix string, fn func(string) error) error // GC 对账
    PublicURL(key string) (string, bool)
    PresignPut(ctx context.Context, key, ct string, size int64,
               ttl time.Duration) (string, error)             // local 返回 ErrNotSupported
}
```

```go
// local 驱动写入：白名单防穿越 + 临时文件 + fsync + rename 原子可见
var keyRe = regexp.MustCompile(`^(orig|var|staging)/[a-z0-9/._-]+$`)
func (l *Local) Put(ctx context.Context, key string, r io.Reader, _ int64, _ string) error {
    if !keyRe.MatchString(key) { return ErrBadKey }
    dst := filepath.Join(l.root, filepath.FromSlash(key))
    os.MkdirAll(filepath.Dir(dst), 0o755)
    tmp, err := os.CreateTemp(filepath.Dir(dst), ".tmp-*"); if err != nil { return err }
    defer os.Remove(tmp.Name())
    if _, err := io.Copy(tmp, r); err != nil { tmp.Close(); return err }
    if err := tmp.Sync(); err != nil { tmp.Close(); return err }  // 照片不省 fsync
    tmp.Close()
    return os.Rename(tmp.Name(), dst)
}
```

图片直出（local 模式）：key 含 sha ⇒ `Cache-Control: public, max-age=31536000,
immutable` + ETag + Range 支持；家庭规模不需要 CDN，浏览器缓存吸收绝大多数请求。

## 8. 安全清单（家庭场景够用的最小集）

- 写接口 Bearer PAT（64 位随机 hex，恒时比较），上传单独限流 10/min；
- 上传三重防御：魔数 / 30MB / 60MP；s3 模式 confirm 后服务端回读复检魔数，
  伪造文件置 failed 并删对象；
- 预签名 URL 锁定 Content-Length + Content-Type，15 分钟过期，key 服务端生成；
- `/img` key 白名单正则 + 路径前缀双校验（防穿越）；
- 变体重编码剥离 GPS；原图不开放公网直链；
- 若时间轴设为私有：变体 URL 加 HMAC 签名（`?e=过期&s=签名`），s3 模式用 PresignGet；
- ⚠️ 前端配套修复：原型 caption 经 innerHTML 拼接，接真实数据前改为
  textContent/HTML 转义，否则存储型 XSS。

## 9. 部署与备份（备份是功能，不是运维附件）

```yaml
# docker-compose —— local 模式（NAS 典型部署）
services:
  shiguang:
    image: ghcr.io/you/shiguang:1.x
    ports: ["8080:8080"]
    environment:
      SG_BLOB_DRIVER: local            # 或 s3 + SG_S3_* 四件套
      SG_ADMIN_TOKEN_FILE: /run/secrets/token
      SG_PUBLIC_READ: "false"          # 家庭默认私有
    volumes: [ "./data:/app/data" ]    # db + blobs 同卷：备份对象只有它
  litestream:                          # SQLite 实时复制到云桶（RPO≈5min）
    image: litestream/litestream
    command: replicate /data/shiguang.db s3://backup/db
    volumes: [ "./data:/data" ]
```

| 数据 | local 模式 | s3 模式 |
|------|-----------|---------|
| 数据库 | litestream 实时复制（或每日 `VACUUM INTO` 快照） | 同左 |
| 图片 | 每日 `rclone sync --backup-dir`（保留删除历史）到云桶，rclone crypt 加密 | 桶开版本控制即可 |

恢复演练（每季度一次）：新机拉镜像 → litestream restore → rclone 取回 blobs →
起服务抽查 10 张图 sha 一致 → 全程应 <1 小时。

配置总表（启动即校验，fail-fast）：

```
SG_ADDR=:8080
SG_DB_DSN=file:data/shiguang.db?_journal=WAL&_busy_timeout=5000
SG_ADMIN_TOKEN(_FILE)      SG_PUBLIC_READ=false
SG_BLOB_DRIVER=local|s3    SG_BLOB_LOCAL_ROOT=data/blobs
SG_S3_{ENDPOINT,BUCKET,AK,SK}   SG_S3_CDN_BASE(可选)
SG_SIGN_SECRET(私有模式)    SG_TRASH_TTL_DAYS=7
```

## 10. 观测、测试与后路

- **观测**：slog JSON 日志（带 trace_id）+ `/healthz`；就三个值得盯的数：
  5xx 率、worker 队列深度、**备份任务是否成功**（照片红线，失败必须告警）。
- **测试**：imgproc 金样测试（8 方向 EXIF、截断文件、炸弹样本）；
  blob 接口契约测试同一套跑 local/fake/MinIO；E2E 复用原型期的 Playwright 脚本。
- **后路（何时需要重新翻开完整版方案）**：照片 >10 万张、出现多实例/多写入端、
  或月外网流量 >500 GB —— 届时按原 v2 方案升级 PostgreSQL / 独立 worker / CDN，
  本精简版的接口与 key 设计已为那天留好缝。

## 11. 实施顺序（单人 3 周）

1. **W1**：schema + timeline/nodes 读 API + local 驱动 + embed 前端 → 原型跑通真数据；
2. **W2**:上传管线 + worker + 变体/BlurHash + 状态轮询 → 批量 200 张全 ready；
3. **W3**：s3 驱动 + presign/confirm + GC/reaper + 备份编排 + 恢复演练。
